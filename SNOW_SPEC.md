# Snow: погоджена концепція прошивки M-VAVE FM-1

Джерело домовленостей: [розмова про власну прошивку](https://chatgpt.com/share/6aeae8ef-aff8-83ed-833e-7ff2b3bff2dc), перечитана 4 листопада 2026 року.

Це специфікація майбутньої прошивки. Вона не означає, що наведені нижче
можливості вже реалізовано. Поточна технічна основа репозиторію — Skiff,
похідний від Felucca; ліцензії та авторство вихідних компонентів зберігаються.
Snow — робоча назва за назвою репозиторію, окрему назву продукту ще не обрано.

## Призначення

Власна шестидоріжкова FM-groovebox для **M-VAVE FM-1**, натхненна підходом
Elektron Model:Cycles: виразні спеціалізовані інструменти, глибоке редагування
та живе виконання. Розробляємо власні алгоритми й інтерфейс.

Останнє рішення в розмові: використовувати **Skiff**, а не Tessera, як основу.
Від Tessera потрібна зручність SAVE, проєктів і патернів. Від Digitakt/Digitone —
напрям піксельного оформлення. Копіювання закритої прошивки не передбачено.

## Шість постійних доріжок

| № | Інструмент | Скорочення |
| --- | --- | --- |
| 1 | KICK | KIK |
| 2 | SNARE | SNR |
| 3 | HAT | HAT |
| 4 | PERC | PRC |
| 5 | BASS | BAS |
| 6 | CHORD | CHD |

- Без семплів: звук створюється синтезом. Шумові компоненти SNARE/HAT також
  синтезуються, а не відтворюються із записів.
- Доріжки прив'язані до своїх інструментів; універсальний вибір сторонніх
  движків у кінцевому інтерфейсі не потрібен.
- Максимально глибоке редагування кожного інструмента через сторінки K1–K4.
  Орієнтир **24–40 параметрів на інструмент** — ціль проєктування, а не
  підтверджена апаратна можливість чи затверджений точний список параметрів.
- Спільні макропараметри: **TONE, SHAPE, SWEEP, DECAY**. Кожен інструмент
  інтерпретує їх відповідно до свого синтезу; детальні параметри — на інших сторінках.
- CHORD має давати акорди; триголосний початковий варіант — пропозиція для
  вимірювання навантаження, а не вже перевірена поліфонія.

## Секвенсор і живе виконання

- До 64 кроків, по 16 на сторінці, окрема довжина для кожної доріжки.
- Кілька **parameter locks** на одному кроці: утримання кроку та обертання ручки
  задає значення параметра для цього кроку.
- Probability, ratchet, microtiming, swing та mute доріжок.
- **Control All** змінює відповідний макропараметр на всіх шести доріжках,
  зберігаючи індивідуальні відмінності; окремі доріжки можна виключити.
- Control All працює поверх параметрів і покрокових locks, не перезаписуючи
  самі locks. Точний закон зміни, насичення та порядок модуляцій треба
  визначити й перевірити під час реалізації.
- **Temporary Save / Reload** зберігає стан у RAM і повертає його під час гри,
  без зупинки або перезапуску транспортної позиції.
- Знімок охоплює всі шість звуків, послідовності нот, locks, налаштування
  доріжок та ефектів. Передбачене також відновлення окремої доріжки.
- Тимчасове збереження відокремлене від постійного запису проєкту у Flash.

Запропонована й прийнята в концепції схема кнопок, яку потрібно перевірити
на конфлікти з керуванням Skiff:

| Дія | Комбінація |
| --- | --- |
| Control All | Утримувати GLO та обертати K1–K4 |
| Temporary Save | GLO + SAVE |
| Temporary Reload | GLO + HOME |

## Модуляція та ефекти

- **Два LFO на кожній доріжці**: окремі призначення, rate, depth, shape,
  phase та синхронізація.
- **Індивідуальна обробка кожної доріжки**, а не тільки спільні send-ефекти.
- Потрібні filter, delay, reverb, chorus та drive/distortion.
- У погодженому розширеному наборі також bitcrusher, phaser/flanger та EQ.
- Ефекти мають власні налаштування й незалежне ввімкнення; їхні параметри
  включаються в locks, Control All там, де це має зміст, і Temporary Reload.
- Шість незалежних важких ланцюгів одночасно ще не перевірені на FM-1.
  Потрібно виміряти RAM, Flash, пікове навантаження та пропуски аудіобуфера.
  Спільна reverb-шина сама по собі не виконує вимогу незалежної обробки.

## Пам'ять і SAVE

- Зручне меню через кнопку **SAVE**, за принципом Tessera: слоти, назви,
  load/save, rename, copy та erase, з окремими розділами для звуків і проєктів.
- Патерни та банки, копіювання й перемикання під час відтворення.
- Постійний проєкт зберігає звуки, ноти, locks, налаштування секвенсора,
  модуляції та ефектів для всіх шести доріжок.
- Кількість слотів і банків не затверджено: її визначать формат і бюджет пам'яті.
- Temporary Reload не перезаписує постійний проєкт.

## Інтерфейс

- Піксельний шрифт, чіткі рамки, квадратні елементи, темний фон,
  світлий текст і жовто-помаранчеві акценти.
- Чотири параметри одночасно, відповідно до фізичних K1–K4.
- Назва, значення і графік параметра одразу реагують на обертання ручки.
- Видимі доріжки KIK/SNR/HAT/PRC/BAS/CHD, кроки та активні locks.
- Графіки огинаючих, LFO, фільтрів і FM-параметрів під дисплей FM-1 240 × 240.

## Робота без встановлення інструментів на Mac

Код зберігається в `Timqos/snow`. Компілятор, SDK та інші залежності працюють
у хмарному середовищі або GitHub Actions. Користувачу не потрібно
встановлювати Docker, SDK, компілятори чи локальний термінальний набір.

Потрібні автоматичні збірки `.fwsc`, завантажувані результати та власна
браузерна сторінка для перевірки звуку, дисплея, кнопок і ручок.
У розмові обрано GitHub Pages для такої сторінки.

У Skiff уже є `web/emu/`: збірка C-коду прошивки у WebAssembly.
Це не тотожне запуску готового `.fwsc` у повному емуляторі процесора.
Вибір між цим симулятором та окремим емулятором `.fwsc` треба робити явно.
Робота в браузері не підтверджує строки виконання DSP на фізичному FM-1.

## Послідовність робіт

1. **Базова хмарна збірка.** Зібрати поточний Skiff без зміни звуку,
   виконати наявні host-тести, отримати справжній `.fwsc` і робочу браузерну
   збірку. Налаштувати GitHub Actions та доступ до результатів.
2. **Архітектура Snow.** Визначити параметри, формати збереження, розподіл
   голосів, пам'яті й процесорного часу та сумісність керування.
3. **Шість FM-інструментів.** Реалізовувати й слухати кожен окремо, потім
   перевірити одночасну гру. Прибирати непотрібні движки з кінцевої збірки.
4. **Ключова логіка виконання.** Locks, Control All з маскою доріжок,
   Temporary Save/Reload, зокрема відновлення під час гри.
5. **Два LFO та індивідуальні FX.** Впроваджувати з вимірюванням бюджету,
   не підміняючи вимогу окремих ефектів спільними sends.
6. **Піксельний UI та SAVE.** Узгодити всі сторінки з фізичним керуванням,
   перевірити збереження, завантаження й перемикання патернів.
7. **Перевірка на FM-1.** Перевірити звук, керування, збереження та найважчі
   комбінації синтезу/FX на апаратурі; результати симулятора не замінюють це.

Поточний етап: базовий Skiff зібрано у `.fwsc` та WebAssembly; підготовлено
workflow хмарної збірки й сторінку симулятора. Власні FM-інструменти Snow та
нове керування ще не реалізовано. Стан публікації перевіряється окремо.
