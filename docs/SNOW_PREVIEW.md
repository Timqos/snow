# Snow 0.1: перший FM-прототип

Це перша зміна синтезу, а не завершення всього [SNOW_SPEC.md](SNOW_SPEC.md).
Режим `FELUCCA_SNOW=1` додає шість машин з новими ID 15–20 та фіксує
їх за доріжками. Звичайна збірка Skiff зберігає вихідні звуки й поведінку.

## Уже реалізовано

- KICK, SNARE, HAT, PERC, BASS, CHORD: власний fixed-point FM-синтез без
  відтворення семплів. На кожну машину три стартові звуки, разом 18.
- Головні ручки: TONE, SHAPE, SWEEP, DECAY. EDIT дає FM DETAIL: окремий
  характерний параметр, FEEDBACK, CUTOFF, DRIVE. Кожен із восьми параметрів
  змінює звук, що перевіряє тест; спільні сторінки огинаючих, LFO й MOD
  розширюють редагування. Остаточних 24–40 спеціальних параметрів ще немає.
- Індивідуальний фільтр і drive, збережений upstream insert та два LFO.
  Повні незалежні chorus/delay/reverb-ланцюги ще не реалізовано: наявні
  send-ефекти Skiff залишаються спільними.
- До 64 кроків, locks, probability, ratchet, microtiming та swing через
  наявний секвенсор. Демо має 16 кроків і приклади locks.
- Control All як адитивний шар над чотирма макропараметрами. Записані locks
  не змінюються. Є маска доріжок.
- RAM Save/Reload усіх доріжок або однієї: параметри, кроки, locks,
  ефекти, offsets та маска. Відновлення не зупиняє transport і не змінює
  його позицію; функції не пишуть Flash. Часткове відновлення відмовляє
  без змін, якщо locks не помістяться в спільні 64 події.
- Збереження проєкту враховує ефективні макропараметри Control All;
  завантаження очищає offsets, щоб не застосувати їх двічі.

## Як слухати

Сторінка прототипу: `https://timqos.github.io/snow/snow/`.
Базовий Skiff лишається на `/snow/try/` для порівняння.

1. **Switch on → Load demo pattern → PLAY**.
2. Вибрати машину кнопкою над панеллю або ручкою ALGORITHM.
3. Крутити K1–K4. PRESETS перебирає три звуки саме цієї машини.
4. Утримувати GLO та крутити K1–K4 для Control All. Shift-click у браузері
   тримає кнопку натиснутою. Чекбокси вгорі задають включені доріжки.
5. Temp Save, Reload all, Reload track доступні кнопками над панеллю.

Фізичне керування: **GLO + SAVE** — Temp Save; **GLO + HOME** — Reload;
**GLO + OCT−** — виключити/включити вибрану доріжку; **GLO + OCT+** —
відновити тільки її. SAVE без модифікатора зберігає звуки/проєкти як раніше.

Завантаження демо замінює поточний патерн. Збереження браузера має окремий
ключ `snow-fm1-prototype-01`, тому не змішується з базовим Skiff.

## Збірка і перевірка

```sh
FELUCCA_SNOW=1 sh build.sh
python3 tools/snow_preview.py
```

Результат: `build/snow-preview/`, включно з WebAssembly та `snow-0.1.fwsc`.
Потрібні ті самі хмарні залежності, що в [CLOUD_BUILD.md](CLOUD_BUILD.md).
CI спершу збирає й перевіряє базовий Skiff, потім Snow, і пакує обидва прев'ю.

`tests/snow_test.c` використовує код прошивки та симульовані апаратні кнопки:
18 звуків, усі 48 машинних параметрів, фіксація ролей, locks, маска,
Reload без зміни позиції, межа пулу locks та відновлення проєкту.
`tests/snow_wasm.mjs` перевіряє завантаження, демо, Control All/Reload під час
гри, обмежений рівень та детермінований звук шести машин у WebAssembly.

RAM-знімок займає 7108 байтів. Вимкнення непотрібного PHYS/GRAIN state у
Snow вивільнило RAM: збірка до кінцевих правок мала pool 310280 із 356352
байтів та зберігала обов'язковий запас 8 КіБ. Остаточні числа див. у логах.
Апаратні перевірки упаковки, RAM/Flash, ROM і HAL лишаються ввімкненими.

Фізичний FM-1 ще не тестувався. Код не встановлює прошивку на пристрій.
Новий екран поки використовує UI Skiff: власне піксельне оформлення та
подальше розширення синтезу/ефектів — наступні етапи.
